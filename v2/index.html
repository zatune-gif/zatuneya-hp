業務の見直し支援（業務改善）

一つの業務・一つの現場を、2か月で見直します。

こんな状態の会社向けです

  • 同じ情報を、何度も入力している
  • 担当者が休むと止まる業務がある
  • 紙とパソコンの両方に同じことを書いている
  • AIを試してはみたが、どこに使うか分からず続かなかった

作るものがもう決まっている場合は、個別実装をご覧ください。

何をするか

  1. 01対象業務の現状分析（作業の洗い出し、かかっている時間の把握）
  2. 02改善案の検討
  3. 03必要に応じたAI候補の比較
  4. 04簡易設定と小規模な試行
  5. 05運用ルールの素案づくりと、次段階で検討する事項の整理

各工程で、現場担当者の方に実際の作業を見せていただく・試していただく場面があります。

終わったときに手元に残るもの

  • 業務の一覧と改善前の数値 — どの作業にどれだけ時間がかかっているかが、社内の共通認識になります
  • 改善案と選んだ理由 — なぜその案にしたかを、後任の方にも説明できます
  • （必要なら）AI候補の比較資料
  • 試した記録 — 実際にやってみて何が起きたかが残るので、広げるか止めるかを判断できます
  • 現場の運用ルール素案 — 誰が・どこまで・何を確認するかの下書きとして使えます
  • 測り方と次の一手 — 期間が終わったあと、社内だけで続きを進められます

含まないこと

  • 本番用の個別システム開発は含みません。仕組みを作る必要があると分かった場合は、仕様を決めてから個別実装として別途お見積りします
  • 対象業務でのAI活用の詳細設計（入力・出力・人が確認する場所・例外時の対応まで詰めた設計）は含みません。AIが役に立つと分かった場合は、オプションのAI活用設計でお受けします

個別実装

仕様が決まった仕組みを、設計・開発します。

こんな状態の会社向けです

  • 業務の見直しは済んでいて、あとは仕組みを作るだけ
  • 既存のサービスと社内のデータをつなぎたい
  • 業務改善の中で、仕組みづくりが必要だと分かった

業務の見直しがまだの場合は、業務改善から始めることをおすすめします。

お見積りの出し方

個別実装は、作るものが決まってからお見積りします。お見積りの前に、次のことを書面で決めます。

  • 何を作るか
  • 既存のどのサービスとつなぐか
  • どのデータを扱うか
  • 誰が何をできる権限を持つか
  • 人が確認する場所はどこか
  • 例外が起きたときどうするか
  • 作ったあとの保守はどうするか（→運用保守へ接続）
  • お客様側で確認していただくこと

この8点が決まってから、作業時間を積算してお見積りをお出しします。仕様を決める作業自体は、業務改善の中で行います。

なお、実装を進める中で、当初の前提（データの形式、連携するサービスの仕様等）が異なることが分かる場合があります。その場合は影響範囲をご説明し、必要であれば追加のお見積りをご案内します。
